# Sacrificial components register

Per ADR-0020. A deliberately-temporary component becomes permanent by accident unless its deletion trigger
is written down. Each entry: **role**, **replacement/deletion trigger**, **guardrails**. Nothing here is
scaffolded empty — every entry is reachable and used now (charter #5), backed by the knip dead-export gate.

| Component | Role | Replacement / deletion trigger | Guardrails |
|-----------|------|-------------------------------|------------|
| **Simulated e-sign provider + webhook** (`src/infrastructure/esign/*`, Phase E) | Proves FlowStep suspend/resume + webhook finalize + idempotency without a real vendor | A real e-sign adapter (DocuSign/Dropbox Sign) is wired behind the e-sign port | Must not present itself as a real signature; HMAC-verified webhook; clearly labeled; never claims legal e-sign validity; the simulate-sign route REFUSES APP_ENV=production |
| **Labeled demonstration seed** (`scripts/seed-demo-store.ts` - the writes - with `scripts/db-seed.ts` as its runner, plus `scripts/seed-decision-ledger.ts`, Phase E; the populated world since ADR-0057) | The labeled dataset the skeleton, its Playwright specs, the house-CRM console, the `/app/ledger` register, the household surfaces and the load gate need | **The populated-world half of the trigger has fired** (ADR-0057 un-defers captain D-005 / ADR-0012): the seed now loads a hundred generated households beside the firm scaffolding. The decision-ledger half is superseded when a real producer appends decision events (v3 prompt 7 ships the append boundary unwired as a named deferral, D-116/D-119); the whole seed is superseded when a real `EvidenceSource` lands (ADR-0024) | Every row carries `asOf` and visible provenance (charter #3): house-CRM rows `source=verin-crm`, world and decision-ledger rows `prov_source='fixture'` rendered behind the synthetic-fixture badge; never feeds a compliance decision (`canFeedComplianceDecision` refuses it); the seed REFUSES APP_ENV=production (publicly committed demo credential); and every row it writes NAMES a demonstration `record_origin` at its insert, so `pnpm fixture:check` can count them (`docs/world.md`) |
| **PGlite dev/CI store adapter** (`src/infrastructure/store/db.ts`, Phase E) | Real Postgres (WASM), hermetic, durable — dev/CI store behind `StorePort` | Production swaps to managed Postgres via the `node-postgres` adapter (D-006) | Same SQL/DDL/triggers as prod Postgres; sacrificial in posture, durable in role |
| **Load-seed generator + p95 gate** (`scripts/load-smoke.ts`, Phase F) | Deterministic pilot-scale seed plus the p95 load gate: store-read, end-to-end flow-step, and concurrency-contention p95 vs the ADR-0014 budget | Superseded if a production-representative load harness replaces it | Seed is deterministic (no `Math.random`), labeled, isolated from real data (an in-process store), and its firm and advisor rows still NAME `record_origin = 'demo-seed'` rather than taking the column's default; the flow-step/concurrency workload deliberately drives the real (randomUUID-keyed, timestamped) write path - the path the SLO measures |

When a trigger fires: delete the component **and prune its doc references in the same PR** (retro
don't-again #42 — the HubSpot stub left doc drift for two review cycles). Demo/seed affordances are also
guarded by the config fail-closed production guards (ADR-0003); a dedicated demo-mode fence lands with
the demo milestone (D-005).
